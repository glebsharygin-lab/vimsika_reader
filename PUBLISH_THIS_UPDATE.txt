Upload these seven files to the root of the GitHub repository, replacing the
existing copies:

1. index.html
2. auth-config.js
3. app.js
4. analysis.js
5. styles.css
6. corpus.js
7. editorial-overrides.json

The new index.html uses asset version 0.17.1 for app.js, analysis.js,
styles.css, and corpus.js, plus version 0.9.1 for auth-config.js, so GitHub
Pages and visitors' browsers fetch the current interface and Worker
configuration.

After GitHub Pages finishes deploying, open:
https://glebsharygin-lab.github.io/vimsika_reader/?v=0.17.1

Expected result:
- the sidebar displays `Build 0.17.1 · Corpus 0.6.0-trial`;
- the main notice begins `Research prototype` and ends `Only for research purposes.`;
- Sources & rights lists 23 witnesses;
- the summary reports 89,652 addressable tokens and 255 numbered sentences;
- verse 1 contains foldable units 1.1 through 1.9 in numeric order;
- every opened witness displays corresponding numbered units;
- collapsed sentences can be hidden, and any sentence can be focused;
- clicking a Sanskrit word highlights its reviewed or projected counterparts;
- Focus mode removes preserved blank space and packs witnesses closely;
- Comparison and Alignment contain clickable token-level surfaces;
- token clicks open a dictionary-ready lexical inspector;
- Analysis opens Lexicon, Concordance, Morphology, Syntax, and Statistics;
- lexical records and CoNLL-U syntax drafts save in the local editorial layer;
- `Edit text & annotations` contains a `Numbered sections` editor where 1.1,
  1.2, etc. can be edited directly as literal section records;
- unnecessary numbered sections can be hidden from Reading and Comparison and
  restored later from the hidden-sections list;
- direct section edits are saved as `sectionEdits`, while legacy token-boundary
  moves remain hidden as an advanced compatibility layer;
- Sanskrit root verses are bold, including interleaved kārikā fragments;
- corresponding sentence spans are bold in every aligned witness.

To publish section, lexical, syntax, and alignment annotations for
collaborators, also replace collaboration-worker/src/index.js with the packaged
version and redeploy the Worker from the collaboration-worker folder:

npm run deploy

The Worker upgrade preserves existing editorial-overrides.json content and adds
sectionEdits, sentenceEdits, lexiconEntries, and syntaxAnnotations during the
next publication.

DharmaNexus matches are not copied into the corpus. An authorized export can be
imported with scripts/build_trial_corpus.py --authorized-alignments FILE.json.
